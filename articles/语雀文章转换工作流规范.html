语雀文章转换工作流规范

目录约定 · YAML规范 · 转换规则 · 自动化流程 · 2026-07-27

第一章

目录约定

drafts路径：C:\Users\ahs\.qclaw\workspace\yuque_export
 转换后的 ：HTML 生成到这里 C:\Users\ahs\Desktop\Project\article-site\articles
 图片放这里：C:\Users\ahs\Desktop\Project\article-site\image
风格模板：C:\Users\ahs\Desktop\Project\arti\技术文档风格规范.md
关键认知：MD 源文件、HTML 输出、图片资源、风格模板分属四个独立目录，各司其职。转换脚本从 yuque_export/ 读取 MD，按风格模板渲染后写入 articles/。
第二章

MD 文件头部格式

每篇 MD 文件必须以 YAML 头部开头，提供三要素：

---
title: 差分放大电路的构建
category: 硬件
date: 2026-05-23
description: 详细推导共射极差分放大电路的增益、CMRR及偏置设计要点
---

正文内容...
注意：YAML 头部必须以三个短横线 --- 开头和结尾，字段间不可有空行，否则解析器无法识别。
字段 说明
title 文章标题，会写入 <title> 和 <h1>
category 9 选 1：硬件 嵌入式 FPGA 高速信号 EMC 控制理论 电机 / EDA / 随笔
date 日期，格式 YYYY-MM-DD
description 一句话简介，显示在首页卡片
第三章

MD 语法 HTML 输出

### 标题 <h3>
![](路径) <img src="../image/..."> 本地路径
![](https://cdn...) 下载到 image/文章名-N.jpg，替换为本地路径
$E=mc^2$ 保留，MathJax 渲染
`代码` <code>
``` 代码块 <pre><code>
**粗体** <strong>
建议：转换时图片路径 ../image/文章名-N.jpg 保持不变，无需额外处理。远程图片则先下载到本地 image/ 目录，再替换引用路径。
第四章

自动化流程

询问用户需要路径下的哪个根目录 → 用户确认 → 自动触发转换 → 调用风格模板 → HTML 写入 articles/ → 自动运行 scripts/scan-articles.py → 自动 git push
注意：Markdown 中的图片路径 ../image/文章名-N.jpg 转换为 HTML 时保持不变。
第五章

知识脉络速记

环节 核心要点 关键约束
目录 四目录分工：MD 源 → articles/ → image/ → 风格模板 路径不可混用，各目录独立
YAML 三要素：title / category / date / description category 9 选 1；date 格式 YYYY-MM-DD；--- 包裹无空行
转换 10 条映射规则：标题 / 图片 / 公式 / 代码 / 粗体 远程图片先下载再替换；本地路径保持不变
流程 确认 → 转换 → 扫描 → 推送，全自动链 逐环节执行，不可跳过 scan-articles.py
核心结论：本规范将语雀导出的 MD 文件按统一风格模板转换为技术文档 HTML，通过四目录隔离、YAML 元数据标准化、10 条映射规则和全自动流水线，实现从草稿到部署的一致性输出。
